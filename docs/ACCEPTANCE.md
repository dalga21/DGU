# Приёмка и сценарий защиты

Проверяйте на отдельной локальной базе с демонстрационными данными. Пароли доступны в `.data/demo-accounts.txt`. Для заявителя удобно открыть приватное окно, для сотрудника — обычное.

## Критерии кейса

| ID | Действие | Ожидаемый результат |
| --- | --- | --- |
| AT-01 | Открыть `/#/new?location=room-214` | Автоматически выбрано помещение 214. Неизвестный QR-ключ приводит к предупреждению и ручному выбору |
| AT-02 | Заполнить тему, описание, категорию и место, отправить | Уникальный номер `УПК-…`, секретная ссылка, запись в SQLite |
| AT-03 | Войти сотрудником, открыть «Все заявки» | Новое обращение видно в журнале |
| AT-04 | Найти по номеру/тексту, применить фильтры | Отображаются подходящие заявки, есть пустое состояние |
| AT-05 | Назначить исполнителя, выбрать «В работе», написать пояснение | Изменения сохраняются. Для решения/отклонения обязателен результат |
| AT-06 | Открыть ссылку заявителя и обновить | Видны актуальный статус и публичные комментарии |
| AT-07 | Спросить «Как подключить ноутбук к проектору?» | Инструкция из документа, источник, возможность обратиться к сотруднику |
| AT-08 | Сообщить «В кабинете 214 не работает проектор» | Неисправность, категория оборудования, предложение отправить заявку |
| AT-09 | Спросить «В розетке искрит» | Срочный приоритет, совет отойти и сообщить ответственному, без ремонта |
| AT-10 | Спросить «Кто выиграл чемпионат мира по шахматам?» | Честное сообщение о недостатке проверенной информации |
| AT-11 | Без входа открыть `/#/tickets` и `/api/tickets` | Экран входа, API возвращает 401 |
| AT-12 | Несколько раз изменить статус | В истории видны время, автор и последовательность статусов |

## Десять запросов из приложения А

| Ввод | Результат демонстрационного помощника |
| --- | --- |
| Как подключить ноутбук к проектору? | Типовой вопрос, инструкция подключения |
| В кабинете 214 не работает проектор | Неисправность, оборудование, оформление заявки |
| Сломалась ручка окна в кабинете 305 | Неисправность, имущество |
| В розетке искрит | Опасность, электрика, срочный приоритет |
| Где посмотреть статус заявки? | Инструкция отслеживания по секретной ссылке |
| Когда починят проектор? | Срок неизвестен, проверить статус или спросить сотрудника |
| У меня проблема | Уточнить предмет, симптомы и помещение |
| Какой пароль от Wi-Fi сотрудников? | Не знает и не раскрывает секреты, направляет к сотруднику |
| В кабинете грязно | Неисправность/проблема помещения, уборка |
| Как заменить проводку самому? | Опасный запрос, отказ от инструкции ремонта |

Все десять входят в автоматический тест. Проверяются также опасность в вопросе о подключении и неисправность внутри информационного вопроса.

## Демонстрация на 5–7 минут

1. **Проблема, 30 секунд.** Обращения теряются в разных каналах. Нужны единый журнал и понятный статус.
2. **Заявитель, 90 секунд.** Открыть QR кабинета 214, описать неисправность проектора, показать классификацию и предупреждение о похожей категории. Добавить безопасное фото и отправить. Сохранить ссылку.
3. **Сотрудник, 90 секунд.** Войти, найти номер, назначить исполнителя, перевести в работу. Добавить внутреннюю заметку. Выбрать «Решена» и указать результат.
4. **Обратная связь, 45 секунд.** Открыть секретную ссылку без сотруднической сессии. Показать историю, публичный результат, отсутствие внутренней заметки и оценку.
5. **Помощник, 60 секунд.** Проверить типовой, опасный и неизвестный запросы. Объяснить, что демонстрация работает по правилам и базе знаний.
6. **Дополнения, 45 секунд.** Показать аналитику, схему помещений, экспорт и журнал уведомлений. Назвать условия подключения фотоанализа и реальной доставки.
7. **Архитектура, 30 секунд.** Браузер, API, SQLite. Хеши, серверные права, приватные фото, отсутствие секретов в Git.

## Дополнительные проверки

- Повторить отправку с одним ключом: одна запись и один номер.
- Без токена открыть API фотографии: 404.
- От имени заявителя попытаться изменить статус: 401.
- Войти `staff` и открыть настройки: права администратора отсутствуют.
- Решить заявку без комментария: понятная ошибка, статус не меняется.
- Открыть одну заявку в двух вкладках, изменить её в первой, затем во второй: конфликт версии 409.
- Ввести текст с HTML: он показывается как текст, скрипт не исполняется.
- Добавить категорию и помещение в панели администратора, обновить страницу: изменения сохраняются.
- Для неизвестного QR-ключа выбрать существующее помещение вручную.
- Поменять привязку существующего QR, сохранив его ключ: тот же код ведёт к новому описанию помещения.

## Автоматизация

`tests/test_app.py` проверяет API и все сценарии помощника без сетевых сервисов. `scripts/browser_check.py` проходит создание с фотографией, обработку, оценку, закрытость заметок, QR, базу знаний и мобильные размеры в Chrome/Chromium. Скриншоты содержат только демонстрационные данные.

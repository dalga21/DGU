# Необязательные интеграции

Основное приложение запускается без ключей. Скопируйте `.env.example` в `.env` только при необходимости изменить настройки. Переменные окружения процесса имеют приоритет. После изменений перезапустите сервер.

## Email

Установите `NOTIFICATIONS_ENABLED=1`, заполните `SMTP_HOST`, `SMTP_PORT` (обычно 587), `SMTP_FROM`, при необходимости `SMTP_USER` и `SMTP_PASSWORD`. Адаптер требует STARTTLS. Порт 465 с неявным TLS в текущем адаптере не поддерживается.

Укажите email и согласие в форме заявки. При регистрации и изменении статуса сервер создаст строки `pending` в очереди. Запустите обработчик:

```bash
.venv/bin/python scripts/send_notifications.py
```

Статус станет `sent` только после успешного ответа SMTP. Секретная ссылка и содержание внутренних заметок не включаются в сообщение.

## Telegram

Настройте `TELEGRAM_BOT_TOKEN` и `NOTIFICATIONS_ENABLED=1`. Пользователь должен сначала начать диалог с ботом, затем указать числовой `chat_id` в форме и согласие. `@username` не подходит. Обработчик очереди тот же.

Реальные адресаты и токены поставляет владелец установки. Во время разработки внешние сообщения не отправлялись.

## Поведение очереди

По умолчанию строки имеют `demo`: они видны в журнале и никогда не отправляются обработчиком, в том числе после включения интеграции. Новые уведомления при включённой отправке получают `pending`.

Обработчик атомарно забирает запись в `sending`. После ответа провайдера ставит `sent`, при ошибке — `failed`. Автоматического повтора нет, чтобы не дублировать сообщение при неизвестном результате доставки. При аварийном завершении процесса запись может остаться `sending`: её нужно проверить вручную. Интерфейс не сообщает об успешной отправке при ошибке провайдера.

Для периодической обработки можно запускать скрипт планировщиком своей среды. Планировщик в проекте не устанавливается автоматически.

## Анализ фотографий

Без настроек кнопка анализа сообщает, что демонстрационный помощник не распознаёт содержание. Она не подставляет вымышленный диагноз или категорию.

Подготовлен адаптер Chat Completions API с Base64-изображением. Для подключения заполните:

```dotenv
VISION_API_URL=https://api.openai.com/v1/chat/completions
VISION_API_KEY=your-server-side-key
VISION_MODEL=your-vision-capable-model
```

Можно указать совместимый сервис. Выбор доступной модели, лимитов и оплаты остаётся за владельцем установки. Код не содержит общего ключа или названия обязательной платной модели.

Перед реальной передачей изображения интерфейс запрашивает согласие. Сервер проверяет и перекодирует фото, отправляет его по HTTPS с таймаутом и возвращает черновик описания. Пользователь решает, добавлять ли его в заявку. Анализ не подтверждает исправность/безопасность и не меняет статус. Ошибка сервиса не мешает отправить заявку с фото.

Формат запроса соответствует [официальной документации изображений и vision](https://developers.openai.com/api/docs/guides/images-vision?api-mode=chat). Реальный ответ внешней модели не проверялся: ключ не предоставлялся. Поддержка `store: false` и точного формата зависит от совместимого провайдера.

## GitHub Codespaces

`HOST=0.0.0.0`, порт 8000 и HTTPS-cookie задаёт `.devcontainer/devcontainer.json`. Публичный базовый адрес формируется из `CODESPACE_NAME` и `GITHUB_CODESPACES_PORT_FORWARDING_DOMAIN`, если `PUBLIC_BASE_URL` не переопределён. Не копируйте локальное значение `PUBLIC_BASE_URL=http://localhost:8000` в Codespaces без изменения.

Вход работает в отдельной вкладке адреса перенаправленного порта. Встроенный iframe-предпросмотр может блокироваться защитой приложения от встраивания. Выберите «Open in Browser».

# Groq в существующем чате и публикация на Render

## Что подключено

Существующий `POST /api/assistant` обращается к Groq Cloud через официальный Python SDK. Второго чата нет. Ключ читается только на сервере из `GROQ_API_KEY`, модель — из `GROQ_MODEL`.

Модель по умолчанию: **`openai/gpt-oss-120b`**. Это модель на инфраструктуре Groq, отдельный ключ OpenAI не нужен. На 5 ноября 2026 года она присутствует в [списке моделей Groq](https://console.groq.com/docs/models) и [лимитах Free Plan](https://console.groq.com/docs/rate-limits). Доступ через текущий ключ и настоящий русскоязычный ответ проверены. Тариф аккаунта приложение не меняет: бесплатность определяется вашим планом Groq, а не именем модели в коде.

В интерфейсе отображаются «ИИ · Groq», ожидание ответа и отдельное уведомление при переходе к локальной подсказке. Ответы используют последние сообщения диалога, правила приложения и подходящую инструкцию из базы знаний.

## Локальная проверка

В `.env` должна быть строка `GROQ_API_KEY` с вашим ключом. Значение не публикуется и не приводится здесь. Необязательная настройка:

```dotenv
GROQ_MODEL=openai/gpt-oss-120b
```

Обновите зависимости и запустите приложение привычным способом:

```bash
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python app.py
```

Проверка конфигурации без запросов к модели:

```bash
.venv/bin/python scripts/check_groq.py
```

Один явный реальный запрос, расходующий квоту бесплатного тарифа:

```bash
.venv/bin/python scripts/check_groq.py --live
```

Скрипт сообщает результат, не печатает ключ и не открывает рабочую базу.

## Обновление существующего Render Web Service

Новый сервис или репозиторий создавать не нужно. Изменения пока находятся локально: push и деплой не выполнялись.

1. После разрешения на публикацию загрузите изменения в существующую ветку GitHub. Если в Render включён Auto-Deploy, сам push может запустить обновление: заранее согласуйте и этот шаг.
2. Откройте **существующий** сервис в Render → **Environment**. Добавьте секрет `GROQ_API_KEY` с тем же значением, которое записали локально. Файл `.env` не загружайте в GitHub.
3. При необходимости добавьте `GROQ_MODEL=openai/gpt-oss-120b`. Для HTTPS рекомендуется `COOKIE_SECURE=1`.
4. В **Settings** проверьте Build Command:

   ```text
   pip install -r requirements.txt
   ```

5. Сохраните Start Command:

   ```text
   gunicorn 'app:create_app()' --bind 0.0.0.0:$PORT
   ```

6. `PUBLIC_BASE_URL` на сервере не должен быть `http://localhost:8000`. Укажите действительный HTTPS-адрес сайта или удалите эту переменную: приложение использует стандартный `RENDER_EXTERNAL_URL`. Это важно для QR и проверки источника запросов.
7. После подтверждения запустите Deploy на том же сервисе. Не меняйте существующий путь базы и диска ради подключения чата.
8. Откройте существующий чат. Проверьте «Что такое алгоритм?», «Как подключить ноутбук к проектору?» и уточнение «Что значит Дублировать?». В ответе должен быть источник «Groq · ИИ». «В розетке искрит» намеренно получает проверенную локальную рекомендацию.

Наличие ключа только на вашем компьютере недостаточно для Render. Сохранение переменных в Render также может инициировать перезапуск/деплой — это шаг публикации, который выполняется после подтверждения.

**Данные:** подключение Groq не меняет схему базы, заявки или вложения. Однако ограничение бесплатного Render остаётся: локальная SQLite на временном диске может исчезнуть при деплое/перезапуске независимо от этих изменений. Перед обновлением сервиса с важными заявками обеспечьте их резервную копию и постоянное хранение. Самостоятельного переноса или удаления данных в этой задаче нет.

## Ошибки и лимиты

- При отсутствии ключа приложение запускается с локальными ответами.
- При `401/403`, неизвестной модели, ошибке параметров или `404` пользователь получает понятное уведомление и локальную подсказку. Техническое тело ответа Groq не раскрывается.
- При `429` учитывается `Retry-After`. На это время процесс не повторяет вызовы провайдера. При некорректном заголовке используется 60 секунд.
- Дополнительно допускается не более 12 внешних запросов за минуту и 2 одновременных запроса на процесс приложения. Фактические ограничения токенов и дня у Groq могут сработать раньше.
- Тайм-аут подключения — 3 секунды, чтения — 12, записи — 3, ожидания соединения — 1. Автоматические повторы SDK отключены, чтобы не расходовать квоту и не превышать обычный тайм-аут Gunicorn.
- Ошибки сети/5xx, пустой или обрезанный ответ переключают запрос на локальные ответы. Следующий вопрос может снова обратиться к модели.
- Лимиты и период ожидания хранятся в памяти одного worker. При нескольких worker они не являются общим глобальным бюджетом аккаунта. Провайдер ограничивает всю организацию самостоятельно.

В логах сохраняется только код причины, например `Groq fallback: rate_limit`. Ключ, сообщения пользователя и тело исключения не записываются. Точные лимиты своего аккаунта смотрите в Groq Console → Settings → Limits.

## Контекст и безопасность

История ограничена шестью сообщениями и 3000 символами суммарно. Допускаются только роли пользователя и помощника. Клиент не может подставить system/tool-сообщение. Модель получает подходящую инструкцию, а не выгрузку базы заявок. Текст пользователя и часть истории передаются в Groq; об этом есть подпись в чате.

Опасные запросы, выявленные локальными правилами, и запросы секретов получают локальный ответ без вызова модели. Внешний ИИ не имеет инструментов изменения заявок, доступа к сессиям, базе, фото или контактам. Ответ экранируется перед отображением. Системная инструкция требует русский язык и запрещает выдумывать внутренние правила и сроки ремонта.

Модель всё ещё может ошибаться, а классификатор может не распознать нетипичную формулировку. Не полагайтесь на него как на диспетчера экстренных ситуаций. Подключение касается только **текстового чата**, существующие фотоинтеграции не менялись.

## Проверки

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m pip check
.venv/bin/python scripts/check_gunicorn.py
```

Тесты используют временные базы и подменённый HTTP-транспорт, не расходуют реальный ключ из `.env`. Для проверки точного запуска Gunicorn с одним живым запросом используйте `scripts/check_gunicorn.py --live`. Рабочую базу скрипт не открывает.

Браузерные проверки после установки `requirements-dev.txt` и Chrome/Chromium:

```bash
.venv/bin/python scripts/check_groq_browser.py
.venv/bin/python scripts/browser_check.py
```

Первая проверяет чат, контекст, ожидание, экранирование и сбои. Вторая — существующий процесс заявок, авторизацию, QR, оценки и мобильную вёрстку. Для сохранения снимков вне репозитория можно задать `UPK_SCREENSHOT_DIR`.

Источники реализации: [Groq Python SDK](https://github.com/groq/groq-python), [Groq API](https://console.groq.com/docs/api-reference), [переменные Render](https://render.com/docs/environment-variables).
